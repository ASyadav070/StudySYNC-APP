Product Requirements Document: StudySync

1. Introduction

1.1. Objective

StudySync is an AI-powered web application designed to help students study more effectively. It achieves this by (1) automatically generating personalized study tools (summaries, flashcards) from uploaded course materials and (2) intelligently matching students into focused study groups based on the exact topics they are studying.

1.2. Target Audience

University and college students.

High school students in advanced courses.

Bootcamp attendees and self-learners.

1.3. Problem Statement

Students often study in isolation, even when enrolled in large classes. Finding a study partner is difficult, and finding one who is studying the same specific topic at the same time is nearly impossible. Furthermore, students spend hours manually creating study aids like flashcards and summaries from dense lecture notes.

1.4. Solution

StudySync is a PERN stack application that solves this by:

File Upload & AI Analysis: Allowing users to upload course materials (PDF, TXT). An AI backend (using the Gemini API) reads these documents and asynchronously generates summaries, keyword lists, and JSON-formatted flashcards.

Intelligent Group Matching: Using the AI-generated keywords as a "fingerprint" for the material, the app identifies and suggests study groups with other users who have uploaded materials with overlapping keywords.

Personalized Study Tools: Providing a clean interface for users to review their summaries and study their auto-generated flashcards.

3. Core Features & User Stories

Epic 1: User Authentication & Profile

User Story 1.1: As a new user, I want to sign up for an account using my email and a password so that I can access the app.

User Story 1.2: As an existing user, I want to log in with my email and password so that I can access my dashboard.

User Story 1.3: As a logged-in user, I want to log out so that my session is securely ended.

User Story 1.4: As a logged-in user, I want my session to persist (using a JWT) so I don't have to log in every time I visit.

Epic 2: Course & Material Management

User Story 2.1: As a user, I want to create a "Course" (e.g., "BIOL 101", "CS 250") so I can organize my study materials.

User Story 2.2: As a user, I want to see a list of all my courses on my dashboard.

User Story 2.3: As a user, I want to click on a course to see all the materials I've uploaded for it.

User Story 2.4: As a user, I want to upload a file (.pdf, .txt) to a specific course.

User Story 2.5: As a user, I want to see the processing status of my uploaded file (e.g., "Processing...", "Completed", "Error").

Epic 3: AI-Powered Study Tools

User Story 3.1: As a user, after my file is processed, I want to click a "View Summary" button to read an AI-generated summary of the document.

User Story 3.2: As a user, after my file is processed, I want to click a "Study Flashcards" button.

User Story 3.3: When I study flashcards, I want to see a "Quiz Mode" UI that shows me a question, and I can click to "flip" the card and see the answer.

Epic 4: Intelligent Group Matching

User Story 4.1: As a user, I want a "Find Groups" page that automatically suggests study groups for me.

User Story 4.2: As a user, I want to see why a group is recommended (e.g., "Matches your topics: 'Photosynthesis', 'C4 Plants'").

User Story 4.3: As a user, I want to join a recommended group.

User Story 4.4: As a user, once in a group, I want to see a list of members.

User Story 4.5 (Bonus): As a user in a group, I want a basic real-time chat room to send messages to other group members.

4. Database Schema (PostgreSQL via Prisma)

This schema should be defined in a schema.prisma file.

// This is your Prisma schema file.
// datasource db defines the database connection.
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

// generator client defines the Prisma Client.
generator client {
  provider = "prisma-client-js"
}

// 1. User Model
model User {
  id        String   @id @default(uuid())
  email     String   @unique
  password  String // This will be a bcrypt hash
  courses   Course[]
  groups    GroupMember[]
  createdAt DateTime @default(now())
}

// 2. Course Model
model Course {
  id        String     @id @default(uuid())
  name      String
  user      User       @relation(fields: [userId], references: [id])
  userId    String
  materials Material[]
  createdAt DateTime   @default(now())
}

// 3. Material Model (The uploaded file)
model Material {
  id        String     @id @default(uuid())
  filename  String
  status    String     @default("PENDING") // PENDING, PROCESSING, COMPLETED, ERROR
  course    Course     @relation(fields: [courseId], references: [id])
  courseId  String
  aiData    AiData?    // One-to-one relationship with AiData
  flashcards Flashcard[]
  createdAt DateTime   @default(now())
}

// 4. AI Data Model (Generated content)
model AiData {
  id          String   @id @default(uuid())
  summary     String
  keywords    String[] // PostgreSQL TEXT[] array for keywords
  material    Material @relation(fields: [materialId], references: [id])
  materialId  String   @unique // Enforces one-to-one
  createdAt   DateTime @default(now())
}

// 5. Flashcard Model
model Flashcard {
  id         String   @id @default(uuid())
  question   String
  answer     String
  material   Material @relation(fields: [materialId], references: [id])
  materialId String
  createdAt  DateTime @default(now())
}

// 6. Group Model
model Group {
  id          String        @id @default(uuid())
  name        String
  description String?
  members     GroupMember[]
  createdAt   DateTime      @default(now())
}

// 7. Group Member (Junction Table for Many-to-Many)
model GroupMember {
  user      User     @relation(fields: [userId], references: [id])
  userId    String
  group     Group    @relation(fields: [groupId], references: [id])
  groupId   String
  joinedAt  DateTime @default(now())

  @@id([userId, groupId]) // Composite primary key
}


5. API Endpoints (Express.js)

All endpoints must be protected by a JWT authentication middleware, except for /auth/register and /auth/login.

5.1. Auth API

POST /api/auth/register

Body: { "email": "user@test.com", "password": "mypassword" }

Response (201): { "token": "jwt.token.here" }

POST /api/auth/login

Body: { "email": "user@test.com", "password": "mypassword" }

Response (200): { "token": "jwt.token.here" }

5.2. Course API

POST /api/courses

Body: { "name": "Biology 101" }

Response (201): { "id": "uuid", "name": "Biology 101", "userId": "user-uuid" }

GET /api/courses

Response (200): [ { "id": "uuid", "name": "Biology 101" }, ... ]

GET /api/courses/:id

Response (200): { "id": "uuid", "name": "Biology 101", "materials": [ { "id": "mat-uuid", "filename": "notes.pdf", "status": "COMPLETED" }, ... ] }

5.3. Material & AI API

POST /api/courses/:id/upload

Type: multipart/form-data

Field: file (the uploaded file)

Response (202): { "id": "mat-uuid", "filename": "notes.pdf", "status": "PROCESSING" }

Action: This endpoint must be asynchronous. It responds immediately after creating the Material record with status: "PROCESSING". The PDF parsing and AI calls happen in the background.

GET /api/materials/:id/summary

Response (200): { "materialId": "mat-uuid", "summary": "This document is about..." } (Fetches from AiData table)

GET /api/materials/:id/flashcards

Response (200): [ { "q": "What is photosynthesis?", "a": "A process..." }, ... ] (Fetches from Flashcard table)

5.4. Group API

GET /api/groups/recommendations

Response (200): [ { "id": "group-uuid", "name": "Photosynthesis Group", "matchingKeywords": ["Photosynthesis", "C4 Plants"] }, ... ]

Logic: This is the most complex query. It must:

Get all keywords for the current user.

Find other users with the most overlapping keywords.

Find groups that those "similar" users are in.

POST /api/groups/:id/join

Response (201): { "userId": "user-uuid", "groupId": "group-uuid" }

6. Asynchronous AI Processing Flow (Critical)

This is the core non-functional requirement.

Request: React POSTS a file to /api/courses/:id/upload.

Server (Initial):

multer saves the file to a temp directory.

Prisma creates a Material record: (filename: "notes.pdf", status: "PROCESSING").

Server immediately sends a 202 Accepted response to React with the new Material object.

Client: React UI updates, showing the new file with a "Processing..." spinner.

Server (Background):

The server, after responding, starts the heavy tasks (this must not block the main thread):

const buffer = await fs.promises.readFile(tempFilePath);

const data = await pdfParse(buffer);

const rawText = data.text;

Call Gemini API 1: const summary = await getSummary(rawText);

Call Gemini API 2: const keywords = await getKeywords(rawText); (Returns a comma-separated string)

Call Gemini API 3: const flashcardJSON = await getFlashcards(rawText); (Returns a JSON string)
.   const flashcards = JSON.parse(flashcardJSON);

Database Transaction:

Create AiData record with summary and keywords.split(',').

Create multiple Flashcard records from the flashcards array.

Update Material record: status = "COMPLETED".

Notification (Bonus):

After the transaction, the server uses Socket.IO to emit a message: io.to(userId).emit('file_processed', { materialId: "mat-uuid", status: "COMPLETED" });

Client (Real-time):

Socket.IO client listeners hear this event and update the UI, removing the "Processing..." spinner.
